# NextComp capabilities and evidence

NextComp makes ongoing agent work accessible from Android while retaining the files, tools, accounts and permissions of the chosen execution environment. The native interface, coordinator and notification path let a person give intent, intervene before completion and continue work away from the desk. Stock Codex performs the work. This document connects that experience to source and bounded evidence so another agent can inspect the system without reconstructing it from release notes.

This is an independent, self-hosted alpha for one owner and trusted devices. The supported backend is vanilla Codex through its experimental app-server. NextComp’s room, Losangelex/LAX and Hollywood entry points were retired on 2026-11-07; native Codex subagents remain supported. This describes the product integration, not the running state of separate native runtimes or services. See [the retirement scope](CODEX-ONLY.md). OpenAI runs Codex inference; Google transports workstation push; the owner operates NextComp's backend. See [privacy](../PRIVACY.md) and [security](../SECURITY.md).

## Interaction and visual design

The Android interface places navigation, keyboard entry and playback controls near the bottom. Either volume key is the primary recording control while the app is in the foreground; there are no microphone tap zones on the current Android list or conversation surfaces. Conversation/list actions use thumb targets, direct card regions and an inline title edit. Cards keep a fixed context height with truncation, live content is paced separately from position, and recency uses a continuous color treatment. Important filters the existing transcript rather than opening a second message list. Activity and compact speech controls stay above the composer; saved spoken passages never become synthetic newest messages. Retained answers keep reply/navigation actions in their actual transcript context. Back returns to the list even with the keyboard open. These choices are inspectable in [the Android UI](../android/app/src/main/java/co/fallsoft/pocket/MainActivity.kt) and [context qualification](qualification/conversation-context-alpha21.json); they are not a comparative ergonomics study.

The NeXT-inspired visual system includes authored dimensional symbols, a voxel N, loading/thinking motion and press deformation rather than only stock glyphs. [SymbolIcon](../android/app/src/main/java/co/fallsoft/pocket/SymbolIcon.kt), [AnimatedMark](../android/app/src/main/java/co/fallsoft/pocket/AnimatedMark.kt) and [PressMotion](../android/app/src/main/java/co/fallsoft/pocket/PressMotion.kt) show the runtime mechanisms; [native symbol qualification](qualification/nextcomp-readable-native.json) and [motion qualification](qualification/nextcomp-symbol-swivel-native.json) record the reviewed assets and native behavior. This visual work is part of the interface, while the ability to carry out a creative task still comes from the selected execution environment.

## Notifications are a return path into the work

There are two complementary paths. Following a session produces automatic completion/failure and supported attention updates. The local `notify_user` MCP tool lets an agent send the update the owner requested, when the requested condition is met, using its actual current thread identity. It can include a useful result, a natural spoken response and explicitly requested attachments. The model never selects an arbitrary recipient.

Workstation delivery passes through the owner's Firebase project to Android. FCM carries the title, bounded preview and routing metadata; full text and attachments use authenticated backend retrieval. Phone-local mode uses a local bridge/foreground monitor and does not require FCM. FCM payloads are not end-to-end encrypted; TLS transport does not make them E2E. Tailscale is not the push transport.

Android notifications open the original task and accept replies. Eligible question/approval actions retain exact outstanding request IDs. Attention items have dismissal, snooze and bounded approximate reminders; resolved or stale requests cannot be treated as current approvals. Ordinary updates can be cleared after a successful visible conversation read, using per-device cursors, while unresolved attention remains. See [notification read policy](NOTIFICATION-READS.md).

Optional speech begins with a short context derived from the input being answered, then reads the response. Notification/manual speech uses a separate ChatGPT-authenticated native audio connection without entering voice mode or accessing the microphone. Captions show the actual spoken chunk, not word-aligned subtitles. Direct Pause/Resume/Clear stays above the composer without dismissing the keyboard; source navigation can open a queued notification's originating session. Completed or paused saved speech does not duplicate the transcript. Lock-screen presentation follows Android privacy/channel settings; secure-screen controls are not bypassed. See [speech data flow](SPEECH-CAPTIONS.md) and versioned qualification before treating native provider availability as pronunciation evidence.

Historical live evidence includes notification replies during active work on the physical phone, idle notification continuation and process-absent FCM in a clean emulator, and resumable physical-phone offline speech. The historical 2026-10-05 phone-network recovery record also documents actual tray delivery after Tailscale restart: [network qualification](qualification/phone-network-recovery-2026-10-05.json). This is an observed recovery, not a permanent DNS fix. FCM acceptance alone is never reported as handset receipt.

## Coordination and execution boundaries

```text
Person on Android
  ├── text / manually controlled voice ── persistent coordinator
  │                                       ├── brief inspection → coordinator answer
  │                                       └── select / create / continue real session
  ├── direct session input ───────────── stock Codex turn / steer / queue
  └── notification reply / question ──── original session or outstanding request

Selected profile: owner-hosted Linux bridge OR phone-local Termux bridge
Useful results return through conversation, retained context, activity and alerts.
```

Coordinator identity and selected session persist per paired device. Voice's audio-only transport transcribes/speaks; a separate stock Codex controller makes task decisions. Native audio uses the host's ChatGPT authentication through a compatible stock CLI, without an APK API key; audio availability/usage is account and runtime dependent. An optional API-key speech implementation is not a requirement of the native path. Acknowledging audio submission is not proof that playback finished.

New tasks default to the owner's full-permissions preference. This is a trusted-owner product, not a project-isolation or multi-user authorization service. Codex's sandbox/approval policy remains authoritative. Phone-local PRoot requires full filesystem access; Android/Termux permissions still apply. Optional phone control requires both Android Accessibility and the app's independent gate, omits passwords, and cannot bypass secure surfaces.

Persistent IDs and outboxes distinguish queued, accepted, failed and unknown outcomes. They reduce ordinary duplication; they are not an exactly-once guarantee across every interruption. The list uses metadata-only discovery and bounded hydration; recent history loads before older pages. Raw model reasoning is excluded. A public reasoning summary or tool action must not be presented as access to private chain of thought.

The additive [computer-use ownership integration](COMPUTER-USE.md) supplies cooperative acquisition instructions to new sessions and exposes redacted broker status. The host broker is installed/configured separately; this does not put a lock around an entire Codex turn or fence every existing browser/desktop tool. Existing tasks remain intact. NextComp’s Hollywood/Losangelex team integration is a retired experiment. Its [backend contract](LOSANGELEX-BACKEND.md), [live peer-delivery evidence](qualification/losangelex-live-backend.json) and [synthetic Android evidence](qualification/losangelex-android-backend.json) remain historical provenance, not supported current operations or a migration of existing stock sessions.

## How this relates to Codex and personal agents

The product question is how a person stays able to direct their computing life as agent work becomes persistent and distributed: how much context must they repeat, when must they look, which intermediate results deserve attention, and how quickly can they reply or redirect? NextComp's implementation provides a concrete place to examine that question across Linux, Android, persistent stock sessions, speech and actionable notifications.

This is an interpretation of its relevance, not an OpenAI roadmap claim or affiliation. Official [Remote connections](https://learn.chatgpt.com/docs/remote-connections) already describes starting/steering work, approvals, outputs and notifications. Official [Dots computers and apps](https://learn.chatgpt.com/docs/dots/computers-and-apps) supports connected personal computers and tasks, while [Dot channels](https://learn.chatgpt.com/docs/dots/channels) connects conversation and calls. Remote control, voice, push and local-computer access alone do not establish differentiation. These sources were checked on 2026-10-05; availability can vary.

A useful conversation would compare concrete continuity and attention behavior, inspect the coordinator's session/action semantics, and evaluate Android as an execution target. A Dot could potentially coordinate these execution environments, but there is no implemented or qualified Dots integration in this release. See the [full briefing](NEXTCOMP-BRIEF.md) and [evaluation method](BRIEF-EVALUATION.md).
