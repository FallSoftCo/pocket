# Catalog and quiet continuation

Recent work uses actual observed item/turn activity and native work recency, never inventory inspection timestamps. Safe delivery holds changes during touch, scrolling and reconnects. Sessions active within the same 30-second age window retain their relative order; newly reactivated work is promoted without a navigation ritual. Rank zero remains the thumb-nearest end.

Product-owned immersion workers have durable identities, including legacy entries from the exact configured private worker directory. They never become public work cards after restart. Delegated agents retain runtime parent ownership. Empty idle shells are omitted from Recent, retained in searchable History, and immediately reappear if they receive meaningful work, are watched, have unread updates or start running. No histories are deleted.

Owner-supplied catalog context supplies a concise evidence-backed blocker or reading aid. It appears only while idle, is invalidated by subsequent real work, does not alter runtime status or activity timestamps, and opens the actual conversation through its card. Titles remain editable. Cached title/topic matches supplement native search, so renamed owners remain discoverable even if the native search index is stale; stale fallback status remains explicitly unverified.

Scheduled reports assemble stored public observations only. They do not call the runtime, invoke a model, start or resume workers. Reporting settings and unread/presented semantics remain unchanged. Stored scope is explicitly incomplete rather than represented as a fresh inventory audit.

`task-checkpoint --state waitingDependency --evidence "..."` parks continuation awaiting an external owner, agent or state change. `needsInput` remains available for questions requiring the user. `continue` requires independent work, rather than a request to recheck unchanged inboxes or wait for replies. A narrow compatibility check parks explicit no-reply dependency checkpoints from older workers. Useful implementation/rendering progress stays eligible.

Dependency holds survive restart and prohibit automatic polling reads or model turns. An owner-audited material `dependencySignal` can re-admit terminal work through the existing continuation endpoint after the normal latest-turn, permission, usage, pending-input and uncertain-delivery checks. Signal identities are consumed once. User commands and explicit cancellations retain their existing control path. This does not deploy the separate running-work enrollment candidate.
