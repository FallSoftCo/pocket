# Room-owned agents

Each project room owns one distinct persistent agent for every explicitly enrolled environment. Each identity has an immutable origin room and host. Global agents originate in a separate typed Global room; they are not reused as project representatives.

One resident runtime per host manages the logical room sessions through that host's original shared Codex app-server. Room initialization adds a separate thread, workspace, configuration and inbox, without adding an OS process, account, service or app-server per room. Preparing identities and reading status do not start model turns. Models run on actual conversational input.

Hollywood allocates the desired identities and memberships, retaining their original operations. The home host creates its own agent credentials and native session. Authenticated federation carries references rather than minting another host's credentials. A fresh matching native observation is required before initialization is ready. Native work, pending questions and initialization remain separate states.

For an existing room, replacements stage without receiving historical inputs. An explicit future-fanout handoff activates the new set. Original accepted inputs, private conversations and unknown outcomes retain their original owners and receipts. Historic authors remain attributable; retained source owners are excluded from the default new-work recipient list.

Android and web consume the same authenticated host descriptors and setup projection. Setup appears in the existing list status and work controls, not an additional permanent header. Missing, malformed, foreign-room or unavailable metadata never asserts readiness. Typed Global and retained legacy projections do not invent an uninitialized fleet.

## Qualification boundary

The candidate has a real isolated PostgreSQL/HTTP allocation, staging, future-fanout, privacy and batched catalog projection qualification. A finite real-native check initialized two distinct threads through one parent process and the original shared app-server, resumed their same IDs and made zero model calls. Original Global context was untouched. Platform adapters include native process/account checks; successful Windows/macOS thread initialization has not yet been qualified. These source and local results do not establish completed cross-host enrollment, a production migration, or physical phone delivery.
