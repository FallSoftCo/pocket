# Human-reviewed Writer context windows

This candidate connects NextComp's room interface to the existing Hollywood human seed-control API and native LAX context replacement. It is opt-in with POCKET_CONTEXT_REVIEW=1 in the installation-owned gateway. It does not switch production defaults or move an agent into a room's identity.

Open the room controls, choose **Context windows**, and select the actual agent when the room has several. Create a review, choose saved work by its human-readable objective, inspect the canonical source text, then prepare and approve the fresh Writer window. Role context is mandatory. Source selection uses the original canonical revision and SHA-256. Prepared content is frozen; changing a held review uses a replacement draft rather than editing an approved packet.

The client keeps the original draft and each operation in private preferences, keyed by source profile, Hollywood binding and agent. It saves an intent before sending. An unconfirmed acknowledgement disables further changes until **Check original action** reads that operation's receipt. Closing the dialog, reconnecting or changing environments does not retarget or resubmit the action. Revision/digest checks, receipts and scoped identity checks support recovery; this is not an exactly-once claim.

The gateway accepts these routes only for a paired human device on its installation-owned Hollywood binding. An owner/admin token is not human-device authority. It admits only validated Writer seed routes and metadata reads; it does not expose arbitrary URLs, native RPC, connector claims or bearer credentials. Hollywood remains the canonical store. Selecting a room message is not a way to inject it directly into a Writer: room interpretation belongs to Reader. Human source discovery reuses the existing purpose-scoped material index.

Selected canonical source bytes and prepared native packet bytes are different measurements. A full provider-input token preview is unavailable. The interface does not claim worker health from configuration or an installed review. Execution activity remains separate from room messages.
