# Human input and agent coordination

The stock gateway's task, reply, reply-recovery, queue-resume and voice-input POST lanes require a paired human device. The shared administrative bearer is an operator credential; it does not identify a human author. Agent coordination uses native interagent messaging, never these lanes. Administrative reads and the operator notification endpoint retain their existing authorization.

The existing server-owned VoiceController API adapter delegates one request using a cryptographically random, single-use capability held only inside the gateway process. It binds the exact method, path and payload to a paired device and a currently thinking persisted voice turn, expires after 35 seconds, and is consumed on inspection. Device removal, completed/uncertain turns, payload changes and replay fail closed. No HTTP endpoint mints capabilities. The adapter releases unused capabilities after the internal request. This preserves the original device for device-scoped effects rather than silently using owner identity.

The human_admissions table stores immutable authenticated creation provenance beside stable task/reply IDs. Task creation copies that provenance to the original start outbox row in the same transaction. Reply admission and its outbox insertion are atomic. Retry/edit/remove and queue-resume actors are append-only actions; retries never replace the original author. Existing accepted receipts, unknown deliveries and their text/states are not rewritten or replayed by this migration. Historical rows with no provenance remain unattributed; wording is not authentication.

Qualification uses the real stock and maintained gateway HTTP routes against disposable SQLite and synthetic upstreams, plus the actual voice controller metadata path and per-request delegation HTTP boundary. No account/profile/model/permission changes or business actions are required. Production activation still requires the owning coordinated quiet cutover; passing tests is not evidence that the guard is deployed.
