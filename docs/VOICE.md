# Voice alpha 8

Pocket uses stock Codex app-server's experimental native WebRTC voice transport and the host's ChatGPT authentication. A separate audio API key is not required. The session list opens the persistent coordinator; a conversation's microphone opens voice with that existing session selected. The coordinator retains context, uses real Pocket control tools, and can return to global coordination with select({coordinator:true}). No prescribed command phrases are required.

The coordinator is pinned above regular sessions in its own mint-accented section. Tapping its row opens chat without recording; its microphone and the launch FAB start recording immediately. One tap on the chat FAB stops recording and automatically sends the completed turn; volume down has the same start/stop behavior. Nonblocking microphone reads make stop independent of another hardware press. The coordinator is a regular chat view with a wide 88dp microphone FAB, secondary text entry behind a keyboard button (Enter sends), replay/pause and an on-screen media-volume slider. Saved transcripts and replies load from device-scoped backend history with pagination, including after app restarts. Manual recording remains local until stop. Completed recordings are delivered to an isolated audio-only native thread. Partial native transcript segments are combined, allowed to settle, and committed once to the durable coordinator. The audio-only thread has a read-only sandbox and any backend handoff is interrupted; it cannot use partial transcripts to perform task work. The coordinator uses the complete transcript and current session focus. Speech is rendered through native voice, buffered into a complete recording, and played with pause/resume/replay. Ending voice does not interrupt work sessions.

Turn IDs and controller/tool results are persistent. Pending recordings survive app process death. After re-entering voice, Pocket checks the existing turn before delivering audio again. Disconnects, server restarts and uncertain tool delivery are reported for inspection rather than automatically replayed. Completed IDs remain pending until response playback begins, so speech preparation failures can replay the saved result without re-running actions.

First-launch prerequisites: paired backend, stock Codex with native voice and ChatGPT sign-in, microphone permission. Accessibility is optional in the foreground and needed for global volume buttons. Android may disable it after updates. A user-visible microphone/media foreground service owns recording and playback. Recordings are 16 kHz mono WAV, capped at 120 seconds; silence is discarded. A lost audio-focus event cancels an unfinished recording or pauses speech. Pocket disconnects native audio after 30 seconds ready and while locally recording, reconnecting on delivery; the persistent coordinator and cached replay remain available. This avoids paying for an idle audio stream. The transport also has a 90-second client lease, renewed every 30 seconds; abandoned connections stop billing after expiry. Stopping voice sends an explicit native stop.

Validation: isolated stock CLI tests without OPENAI_API_KEY or CODEX_API_KEY established connected WebRTC, transcribed a complete recorded request across multiple native segments, rendered a supplied response and completed buffered playback. Server regression tests cover latest-message selection, bounded preview hydration, audio-thread isolation, owner checks, combined transcripts and idempotent commit. Android unit tests/build/lint and emulator checks are recorded during release qualification. Physical Pixel lock-screen/background key behavior and Bluetooth routing require device checks; emulator qualification does not establish those hardware behaviors.

Limitations: native voice is experimental and depends on account/CLI compatibility and network access. Rendering and buffering full responses trades some startup latency for reliable manual pause/replay. Audio arrives at native voice in real time after recording finishes. Transcription settlement is bounded; disconnected or missing transcripts are retried without executing partial work. Native desktop credit pricing is documented, but the exact promotional-grant debit through CLI transport has not been measured. No silent fallback to separately billed API audio occurs.

Generic error WAV assets were authored using Mini TTS, Marin, on October 2, 2026; they contain no user/task data. The older API audio adapter is retained for compatibility but is not used by the new default voice flow.
